# Подробное руководство pane-md

[Краткое описание на русском](../README.ru.md) · [English README](../README.md)

Локальный блокнот для чтения, правки и ревью Markdown. Windows 10/11 x64 использует нативный редактор RichEdit. Графическая версия для Linux и macOS использует системный WebView. Команды анализа и MCP-сервер доступны на трёх платформах. Комментарии сохраняются внутри документа.

## Сборка и запуск

Установите Rust 1.95 или новее для `x86_64-pc-windows-msvc` и Visual Studio Build Tools с Windows SDK. Соберите из корня проекта.

```powershell
cargo build --release --locked
.\target\release\pane-md.exe "C:\docs\Мой документ.md"
.\target\release\pane-md.exe "C:\docs\Мой проект"
.\target\release\pane-md.exe --source --wait "C:\temp\prompt.txt"
```

На Linux для сборки графической версии нужны GTK 3, WebKitGTK 4.1 и `pkg-config`. На Debian 12 установите пакеты `libgtk-3-dev` и `libwebkit2gtk-4.1-dev`. Для запуска готового бинарника нужен установленный WebKitGTK 4.1 и сеанс X11 или Wayland. Соберите и запустите из корня репозитория.

```sh
cargo build --release --locked
./target/release/pane-md "Мой документ.md"
./target/release/pane-md --source --wait "Мой документ.md"
```

Для CLI и MCP без графических библиотек на Linux и macOS используйте `cargo build --release --locked --no-default-features`.

После компиляции запустите `python scripts/package-windows.py` на Windows или `python3 scripts/package-linux.py` на Linux x64. Архив в `target/release` включает программу, лицензии зависимостей и ссылки на исходники, в том числе на реализацию ELK.

### GitHub Actions и релизы

`.github/workflows/ci.yml` запускается для изменений в `main`, pull request и вручную. На Windows, Linux и macOS он проверяет форматирование Rust, Clippy, тесты и метаданные пакетов, затем собирает архив для каждой платформы. На Linux дополнительно запускаются компонентные проверки интерфейса в Chrome. Архивы доступны в артефактах запуска Actions 14 дней.

Для публикации релиза установите версию в `Cargo.toml` и отправьте тег `v<версия>` (например, `v0.1.0`). Workflow отклонит тег с другой версией, соберёт Windows ZIP, Linux TAR и универсальный macOS ZIP, создаст `SHA256SUMS.txt` и опубликует GitHub Release. У задания публикации есть право записи; сборки и проверки используют только чтение репозитория. До отправки проекта на GitHub workflow проверен локально, но сам запуск на GitHub runner ещё не выполнен.

### macOS

Для сборки приложения нужны macOS 13 или новее, Rust 1.95 или новее, Python 3 и Xcode Command Line Tools. Скрипт собирает исполняемый файл для Intel и Apple Silicon, объединяет обе архитектуры и добавляет значок Finder. Графический интерфейс использует системный WKWebView. [Документация Apple об универсальных приложениях](https://developer.apple.com/documentation/apple-silicon/building-a-universal-macos-binary)

```sh
xcode-select --install
rustup target add aarch64-apple-darwin x86_64-apple-darwin
python3 scripts/package-macos.py
ditto -x -k target/release/pane-md-macos-universal.zip target/macos
open -a "$PWD/target/macos/pane-md.app" "$PWD/README.md"
```

Скрипт применяет локальную подпись ad hoc, распаковывает архив для проверки подписи и архитектур и запускает `--version` из извлечённого приложения. Для публичной дистрибуции за пределами Mac App Store Apple рекомендует подпись Developer ID и нотариализацию. [Документация Apple о нотариализации](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)

Сборка и запуск `.app` требуют macOS. Проверка компиляции для обеих архитектур на Windows не подтверждает работу окна, CLI или MCP на Mac; перед распространением выполните приведённую команду и сквозные проверки на настоящем Mac.

Для CLI и MCP используйте файл `target/macos/pane-md.app/Contents/MacOS/pane-md`. С аргументами `--mcp` и `--source --wait PATH` он сохраняет протокол и поведение терминального запуска. Finder показывает приложение в меню «Открыть с помощью» для Markdown-файлов.

### Интерфейс Linux и macOS

Версия с WebView поддерживает вкладки, проводник, оглавление, Markdown, редактирование и форматирование WYSIWYG, таблицы, флажки задач, локальные и встроенные изображения, SVG, поиск, переходы по ссылкам, диаграммы Mermaid и работу с карточками комментариев. У сетевого изображения нажмите «Загрузить изображение», чтобы показать его в документе. Доступны русская и английская локализации, а также светлая, тёмная и системная темы.

В версии с WebView комментарий можно привязать к выделению в WYSIWYG или исходнике. Нажмите `Ctrl+Alt+M` или «+» в панели комментариев. Карточка ведёт к цитате и показывает действия для правки, решения, перепривязки и удаления. `Ctrl+Alt+E` правит выбранный комментарий, `Ctrl+Alt+R` переключает его статус, `Ctrl+Alt+L` перепривязывает его к текущему выделению, `Ctrl+Alt+D` открывает подтверждение удаления. `Ctrl+Enter` применяет черновик, `Esc` отменяет его, `Ctrl+S` сохраняет документ. На macOS вместо `Ctrl` можно использовать `⌘`.

В Linux и macOS команды WYSIWYG доступны в меню «Формат» в режиме редактирования. Выделите текст для полужирного, курсивного, зачёркнутого или моноширинного оформления и вставки ссылки. Для заголовка, списка и таблицы поставьте курсор в нужный блок. В ячейке доступны добавление и удаление строк и столбцов. `Ctrl+B`, `Ctrl+I`, `Ctrl+K`, `Ctrl+Alt+1…6` и `Ctrl+Shift+L` запускают команды с клавиатуры. `Enter` разбивает простой абзац, добавляет абзац в конце документа или продолжает список, `Shift+Enter` добавляет перенос внутри поддерживаемого текстового блока. Для диапазонов со сложной разметкой редактор сохранит исходный текст и подскажет перейти в Markdown.

В WYSIWYG `Ctrl+V` вставляет обычный текст из буфера обмена, на macOS используется `⌘+V`. Один перенос остаётся внутри блока. Пустая строка в обычном абзаце разделяет абзацы, а в ячейке, заголовке или пункте списка остаётся внутри блока. В файле переносы внутри блока сохраняются как `<br>`, а в блоках кода сохраняются окончания строк документа. Вставку можно отменить одним шагом.

Выделение через несколько обычных абзацев можно заменить вводом или вставкой, удалить либо вырезать. Если правка объединяет абзацы, скрытые записи комментариев переносятся после объединённого текста. Карточки к удалённым цитатам можно перепривязать. `Ctrl+Z` отменяет такую правку целиком.

Чтобы добавить изображение в WYSIWYG, выберите «Вставить изображение…» в меню форматирования или нажмите `Ctrl+Shift+K` (`⌘+Shift+K` на macOS). Изображение добавляется отдельным блоком после текущего блока документа. Файл внутри папки документа получает относительную ссылку. Для файла из другой папки редактор создаёт копию рядом с документом и подбирает свободное имя. Отмена удаляет ссылку из документа, а копия остаётся в папке. Поддерживаются PNG, JPEG, GIF, WebP, BMP и SVG.

## Проверка Markdown и чтение комментариев

```text
pane-md --lint README.md PROMPT.md
pane-md --lint --json README.md
pane-md --list-comments README.md
```

Линтер проверяет якоря заголовков, наличие локальных файлов и изображений, а также записи комментариев и их привязки. Относительные ссылки разрешаются от папки документа. Для ссылки с якорем в другом Markdown-файле линтер читает сохранённый файл и проверяет заголовок. Сетевые URL пропускаются. В обычном выводе у каждого замечания указан путь, строка и столбец. `--json` возвращает массив отчётов по файлам. Код выхода `0` означает, что замечаний нет, `1` означает, что линтер нашёл замечания, а `2` означает ошибку команды или чтения проверяемого файла. Для путей, начинающихся с дефиса, поставьте `--` перед первым путём.

`F8` и `Shift+F8` переходят к соседней проблеме в открытом буфере с учётом несохранённых правок. Строка состояния показывает место и причину. Команда `--list-comments` возвращает JSON с сохранёнными комментариями и ошибками их разбора.

## Работа в графическом редакторе

Ассоциация `.md` не требуется. Можно открыть файл перетаскиванием, нажать `Ctrl+O` для файла или `Ctrl+Shift+O` для папки. Папки читаются по мере раскрытия. `Ctrl+Tab` переходит к следующей вкладке, `Ctrl+Shift+Tab` возвращает к предыдущей, `Ctrl+W` закрывает вкладку, `Ctrl+S` сохраняет. При конфликте на диске можно сохранить буфер под новым именем через `Ctrl+Shift+S`.

«Файл → Новая заметка» или `Ctrl+N` (`⌘+N` на macOS) открывает пустую вкладку в режиме правки WYSIWYG. Первое сохранение предлагает выбрать имя и папку. Отмена оставляет текст во вкладке. При закрытии изменённой заметки редактор предлагает сохранить её, закрыть без сохранения или вернуться к правке. Перед вставкой локального изображения или переходом по относительной ссылке сохраните заметку, чтобы у неё появилась папка.

`F5` или «Вид → Обновить файлы папки» перечитывает раскрытые ветки дерева и оставляет вкладки открытыми. Щелчок по папке раскрывает или сворачивает её на месте. Если открыть уже открытую заметку из проводника, редактор переключится на её вкладку. В дереве WebView стрелки вверх и вниз выбирают соседнюю строку, вправо раскрывает папку или ведёт к первому дочернему элементу, влево сворачивает папку или возвращает к родительской строке. `Enter` активирует строку.

В Linux и macOS команда «Файл → Выход» закрывает окно. Перед закрытием редактор предлагает сохранить изменённые вкладки.

Переключатель «WYSIWYG / MD» меняет отрисованный документ и буквальный Markdown, включая встроенные записи ревью. Соседний переключатель задаёт режим в обоих представлениях.

| Режим | Назначение |
| --- | --- |
| Только чтение | Чтение без подсветки и панели комментариев |
| С комментариями | Чтение и ревью. Этот режим включён при открытии файла |
| Редактирование | Редактирование документа и обсуждение выделений |

`Ctrl+1` и `Ctrl+2` открывают чтение в WYSIWYG и MD. `Ctrl+3` и `Ctrl+4` открывают правку. `Ctrl+F` ищет, `F3` и `Shift+F3` переходят по совпадениям. `Ctrl+Enter` открывает ссылку под курсором в WYSIWYG и MD. В режиме правки и в исходнике работает `Ctrl+клик`. `Alt+←` и `Alt+→` перемещают назад и вперёд по истории ссылок. Масштаб меняют кнопки внизу, `Ctrl++` и `Ctrl+-`. На Windows работает также `Ctrl+колесо`. Меню «Настройки» предлагает светлую, тёмную и системную темы и переключает русский и английский. Приложение запоминает тему и язык.

Поиск воспринимает запрос как обычный текст и поддерживает параметры «С учётом регистра» и «Только целые слова». В режиме редактирования Markdown `Ctrl+H` или «Правка → Заменить…» открывает замену. В поле замены `Enter` заменяет текущее совпадение, `Ctrl+Enter` заменяет все. На macOS можно открыть замену через меню «Правка» и применить её ко всем совпадениям с помощью `⌘+Enter`. Служебные записи комментариев сохраняются, массовая замена отменяется одним действием.

В меню «Настройки → Оформление редактора» можно выбрать гарнитуру и размер отдельно для WYSIWYG и Markdown. Шрифт Markdown также используется для кода в WYSIWYG. Цвета фона, текста и ссылок сохраняются отдельно для светлой и тёмной тем. При смене фона редактор подбирает читаемые цвета, если прежние потеряли контраст. Команда «Сбросить шрифты и цвета» возвращает оформление редактора к стандартному. В версии с WebView фон, текст и ссылки можно настроить отдельно для обеих тем в одном диалоге. Размеры шрифтов задаются в пунктах.

Стрелки в заголовках сворачивают боковые панели. После сворачивания стрелка у края разворачивает панель. Выбор пункта оглавления переносит к заголовку в документе. Дерево папки доступно из меню «Вид». В узком окне боковые панели открываются по очереди, чтобы оставить место документу. `F6` переносит фокус между документом и открытыми панелями. В WebView `Shift+F6` меняет направление обхода. Крестик на вкладке закрывает её с обычной проверкой несохранённых изменений.

В WYSIWYG можно заменить, удалить или вырезать выделение через несколько форматированных фрагментов одного абзаца, заголовка, пункта списка или ячейки. При замене через соседние пункты списка выбранные пункты объединяются, а маркер и флажок первого сохраняются. При выделении нескольких ячеек одной таблицы новый текст попадает в первую, строки, столбцы и выравнивание сохраняются. В Windows RichEdit выделяет ячейки целиком при переходе между столбцами. `Ctrl+Z` отменяет замену за один шаг.

В неполных строках таблицы можно заполнять видимые пустые ячейки, добавлять и удалять строки и столбцы. Ввод в пустую ячейку дописывает разделители до её столбца. При добавлении столбца короткие строки могут оставаться короткими. Лишние скрытые поля сохраняются при правке столбцов. Чтобы сделать строку с такими полями заголовком, отредактируйте её в MD.

В таблице `Tab` переходит к следующей ячейке, а `Shift+Tab` возвращает к предыдущей. `Tab` в последней ячейке создаёт строку и ставит курсор в её первый столбец. После добавления строки или столбца курсор переходит в новую ячейку. После удаления он переходит в ближайшую оставшуюся.

Выделение между соседними абзацами, заголовками и пунктами списка можно заменить в WYSIWYG; результат сохраняет тип первого блока. Маркер и флажок сохраняются, если первым был пункт списка. Для остальных правок через разные типы блоков используйте режим MD. Изображения из относительных путей показываются в WYSIWYG. Поддерживаются PNG, JPEG, SVG и растровые форматы, которые декодирует Windows, например BMP, GIF и TIFF. В редакторе Windows для GIF показывается первый кадр. Поддерживаются и встроенные изображения `data:image/...;base64,...`. Нажмите на подпись сетевого изображения, чтобы загрузить его внутри документа. Загрузка идёт в фоне и ограничена 8 МБ и 6 секундами. После загрузки нажатие на изображение открывает ссылку.

В режиме редактирования WYSIWYG `Ctrl+Shift+L` превращает абзац или пункт списка в задачу. Нажмите на флажок или используйте `Ctrl+Пробел`, чтобы изменить состояние задачи. На Windows `Ctrl+Пробел` работает и в исходнике MD. `Enter` продолжает маркированные, нумерованные и вложенные списки. Для задачи создаётся новый пункт с пустым флажком. Повторный `Enter` на пустом пункте в конце документа возвращает к абзацу. `Shift+Enter` переносит строку внутри пункта. В меню «Формат» можно выбрать маркированный или нумерованный список и заголовок H1–H6. Для уровней заголовков работают `Ctrl+Alt+1`–`Ctrl+Alt+6`.

Рендеринг поддерживает темы документа, ELK и формулы в метках диаграмм. Блоки с ошибками, превышающие 64 КиБ или исчерпавшие лимит предпросмотра, остаются в виде исходника. Для документа учитывается до 128 разных диаграмм с суммарным исходником до 1 МиБ. Встроенные интерактивные действия и загрузка внешних ресурсов в предпросмотре отключены. Формулы Markdown вне диаграмм показываются исходником.

При переключении режимов и вкладок сохраняются выделение и видимая область. «Вид → Показать в исходнике» открывает Markdown на текущем выделении или соответствующем блоке. «Вид → Найти заголовок» ищет без учёта регистра по заголовкам, включая несохранённые. `Enter` и `F3` идут к следующему совпадению, `Shift+F3` — к предыдущему. Поиск продолжается с другого конца файла после последнего совпадения.

Ссылки на заголовки работают внутри файла и между Markdown-документами. Сноски ведут к определению и обратно к первому упоминанию. Команды «Назад по ссылке» и «Вперёд по ссылке» в меню «Вид» восстанавливают вкладку, представление и позицию. На macOS для них используются `⌘+[` и `⌘+]`. Если вкладку закрыли, редактор может заново открыть сохранённый файл. Новый переход по ссылке заменяет путь вперёд от текущего места. Поддерживаются относительные и абсолютные пути, `file:` и ссылки на распространённые вложения. Веб-ссылки и адреса `mailto:`, `tel:`, `sms:` и `ftp:` передаются системному обработчику. Другие URI-схемы отклоняются.

В правке WYSIWYG нажмите `Ctrl+K` (`⌘+K` на macOS), чтобы создать или изменить ссылку. Для новой ссылки выделите текст. Для правки поставьте курсор в существующую ссылку. Подпись, форматирование и всплывающая подсказка сохраняются. При изменении ссылки по идентификатору выбранное вхождение станет обычной ссылкой с новым адресом. Остальные вхождения продолжат использовать общее определение. Чтобы снять ссылку, в Windows очистите поле адреса и нажмите «Применить», а в WebView нажмите «Снять ссылку». `Ctrl+Z` отменяет правку.

## Ревью

Выделите текст и нажмите `Ctrl+Alt+M` или «+» в панели комментариев. На Windows после выделения мышью нескольких строк открывается меню с копированием, комментарием и вырезанием. Вырезание доступно в правке.

Карточка справа показывает цитату и текст комментария. Нажатие выделяет соответствующий фрагмент в документе. Меню «Ещё» открывает правку, удаление, смену статуса и действия с привязкой. `Ctrl+Enter` применяет черновик к буферу, а `Ctrl+S` сохраняет файл. На Windows кнопка «Сохранить» также записывает файл, а пункт «Вид → Все комментарии» показывает записи за пределами экрана и записи без привязки. В WebView кнопка «Сохранить» применяет черновик к буферу.

Версия 1 записывается как `<!-- pane-md:review {…} -->` после последнего блока выделения целиком. Необязательное поле `anchor.span` задаёт число последовательных областей текста у выделения через несколько блоков, а `updated_at` хранит Unix-время последнего изменения в миллисекундах. У старых записей без этого поля дата помечается как неизвестная до первого изменения. Значения `row` и `cell` считаются с нуля, строка заголовка таблицы имеет `row: 0`. `line` и `column` в результате MCP начинаются с единицы, столбец измеряется в байтах UTF‑8. `bytes` — полуоткрытый диапазон в UTF‑8 без BOM. RichEdit использует отдельные позиции UTF‑16. Заголовок, координаты ячейки и текст по краям помогают восстановить выделение при внешней правке.

Документы с прежней меткой `notepad-md:review` продолжают открываться, а новые комментарии получают метку `pane-md:review`. Настройки из прежней папки или ключа реестра читаются до первого сохранения настроек под новым именем.

## Внешний редактор Codex

Задайте `VISUAL` в том PowerShell, из которого запускаете Codex CLI. `Ctrl+G` в поле набора открывает временный промпт. Сохраните и закройте окно редактора, чтобы вернуть правку в поле набора. [Документация Codex CLI](https://learn.chatgpt.com/docs/cli-customization#prompt-editor)

```powershell
$exe = (Resolve-Path .\target\release\pane-md.exe).Path
$env:VISUAL = '"' + $exe + '" --source --wait'
codex
```

Режим `--source --wait` проверен с правкой, сохранением и чтением того же пути для `.txt` и файла без расширения. Сквозная проверка клавиши `Ctrl+G` в установленном Codex CLI 0.170.0 осталась неполной. Автоматизированная консоль не запустила редактор по этой клавише.

## MCP

```toml
[mcp_servers.pane-md]
command = 'C:\apps\pane-md.exe'
args = ['--mcp']
```

Все инструменты принимают объект с полем `path`. Относительный путь считается от рабочего каталога сервера.

- `list_comments` читает сохранённый файл и возвращает `comments` и `diagnostics`.
- `lint_document` запускает ту же проверку, что и CLI, и возвращает `issues`.
- `open_document` доступен в графических сборках Windows, Linux и macOS. Он запускает отдельное окно WYSIWYG и возвращает `path` и статус `launched` после создания процесса. Окно остаётся открытым после отключения MCP-клиента. На Linux требуется сеанс X11 или Wayland.

`STDOUT` содержит протокол MCP, `STDERR` содержит диагностику. При закрытии входного потока сервер завершает работу.

## Тесты и проверка Rust

```text
cargo fmt --all -- --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --locked
```

Структуру пакетов можно проверить командой `python3 scripts/test-packaging.py`. На Windows используйте `python` вместо `python3`.

На всех платформах Rust-тесты проверяют Markdown, CLI и обмен сообщениями с MCP-сервером. Нативные тесты окон и RichEdit запускаются на Windows. Тесты Mermaid в графических сборках проверяют все 34 семейства диаграмм, математические формулы и раскладку ELK.

Для сквозной проверки Linux установите `xdotool`, `xclip` и ImageMagick. В сеансе X11 или Xvfb запустите команду ниже. Тест проверяет создание заметок и первое сохранение, вкладки и обновление проводника, переходы по ссылкам и возврат к прежней позиции, сохранение Markdown, поиск и замену, карточки комментариев, появление диаграммы и переход к её исходнику, применение и восстановление оформления, редактирование структуры, сохранение привязки комментария после форматирования, вставку из системного буфера обмена и выбор изображения в системном диалоге.

```sh
python3 scripts/smoke-portable.py target/release/pane-md
```

Добавьте `--export-workspace target/ui-snapshots`, чтобы сохранить снимки работающего окна в трёх состояниях. Тест открывает WYSIWYG и MD с оглавлением, затем сворачивает оглавление и редактирует один из трёх комментариев в карточке.

Сценарий Linux также проверяет поиск и сохранение правки посередине исходника на 30 000 строк. Компонентную проверку слоя номеров строк можно запустить командой `python scripts/test-source-pane.py`. Для неё нужен Chromium или Chrome. Путь к браузеру можно указать в `CHROME_PATH`.

Кнопки и значки служат атомами, а вкладка и переключатели режима — молекулами. Карточка комментария и строка исходника составляют клетки. Панели оглавления, документа и комментариев собирают их в рабочую область. Windows и WebView берут цвета из `src/appearance.rs`, а русские и английские строки из `src/i18n.rs`.

## Проверка Windows

```powershell
cargo test --locked
python -X utf8 scripts/fixture.py 'target/Проверка Windows'
python -X utf8 scripts/smoke.py target/release/pane-md.exe 'target/Проверка Windows/Большой документ.md'
```

Сценарий проверяет запуск, завершение, MCP, навигацию и сохранение. Он печатает время первого показа пустого окна и файла с 160 пятиколоночными таблицами, а также рабочий набор памяти. Показатели зависят от текущей сборки и нагрузки компьютера; для сравнения используйте вывод этого сценария, а не прежние замеры. Реализация окна Windows находится в `src/desktop`, команды терминала и STDIO-сервер находятся в `src/cli.rs` и `src/mcp.rs`.

### Переключение между чтением и правкой

`--mode-switch` измеряет переключение WYSIWYG между чтением и правкой с вызовом `UpdateWindow`. Окно остаётся за пределами экрана; результат содержит медиану и p95 после прогрева.

```powershell
python -X utf8 scripts/smoke.py target/release/pane-md.exe 'target/Проверка Windows/Большой документ.md' --mode-switch
```

### Задержка ввода в WYSIWYG

Флаг `--typing` измеряет вставку символа в обычный абзац до синхронизации буфера и вызова `UpdateWindow`. Скрипт сверяет сохранённые байты после 50 вставок и исключает первые 10 замеров. Быстрое обновление карты применяется к простому тексту и ячейкам в документах без записей ревью. Для форматирования и обновления привязок комментариев используется полный разбор.

```powershell
python -X utf8 scripts/fixture.py 'target/Проверка ввода' --sections 1000
python -X utf8 scripts/smoke.py target/release/pane-md.exe 'target/Проверка ввода/Большой документ.md' --typing
```
